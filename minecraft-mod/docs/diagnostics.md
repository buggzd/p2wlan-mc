# Mod 启动诊断与日志

[安装指南](quickstart.md) · [技术参考](../README.md)

本页说明 Fabric / Minecraft 1.21.1 Mod 的启动诊断，用于定位初始化、文件操作和助手启动故障。

## 游戏内查看

1. 打开菜单按钮旁的 P2WLAN 像素图标。
2. 点击「诊断日志」。即使助手启动失败、尚未登录或登录按钮禁用，这个入口仍可使用。
3. 页面显示助手状态、稳定错误码、初始化阶段、失败操作、逻辑文件类别及系统错误码。缺少记录的项目显示未知。
4. 点击「复制诊断」，将脱敏摘要粘贴给维护者；也可点击「打开日志目录」取得文件。

`INITIALIZATION_FAILED / PROFILE_IO` 表示本机私有配置初始化期间的文件操作失败。结合失败操作和数字系统错误码定位对应文件访问。不要通过删除账号配置、放宽 ACL 或关闭安全检查来试错。

Windows 目录错误区分 `DRIVE_ROOT`（本地盘符根目录）、`ANCESTOR`（普通祖先目录）和 `PROFILE_DIRECTORY`（私有配置目录）。目录层级从盘符根目录的 `0` 开始；这些标签不包含真实盘符或目录名。系统错误码标明失败类别；定位占用进程需结合系统工具检查。

## 文件位置

日志位于 **该游戏实例的实际运行目录**：

```text
logs/p2wlan-mod/startup.log
logs/p2wlan-mod/startup.log.1
```

HMCL 的启动器目录不一定是游戏运行目录；使用版本隔离时应查对应实例目录。`startup.log` 是当前段，`.1` 是上一轮转段。每段最多 256 KiB，仅保留一个备份；`startup.lock` 是空的写入者锁，不需要提交。

日志独立于 `config/p2wlan-private/`，在私有配置无法读取或原生程序未启动时仍可记录 Java 的启动阶段与失败码。目录不可写、被占用或文件不安全时，页面会明确显示文件日志不可用；此时使用「复制诊断」，不要去修改私有配置权限。

## 记录与隐私边界

日志记录本次启动标识、时间、事件序号、系统／CPU 架构、Java 主版本与位数、已验证原生包的版本／源码提交／摘要、资源提取、子进程启动、IPC 握手、失败、退出及清理事件。原生文件 I/O 错误只附带固定操作标签、逻辑文件类别、数字系统错误码和可选目录层级，不记录真实目录名。

不会记录账号邮箱、密码、Control URL、token、密钥、完整配置、IPC 请求／回复、游戏载荷、原始 stderr 或异常文本。日志不会自动上传。复制内容不包含本机绝对路径。

内存保留最近 64 条、每条最多 1024 字符；磁盘写入队列最多 128 条，由一个随启动生命周期结束的后台线程处理。摘要标明内存淘汰和队列丢弃数量；磁盘失败保留固定原因码，仍可复制内存摘要。日志用于故障反馈；会话、房间和路径状态由原生运行时管理。

## 显示设置保存

点击「保存并返回」会记录 `DISPLAY_SETTINGS_SAVE`，目标固定为 `DISPLAY_SETTINGS`。`reason` 表示保存结果，`operation` 区分路径检查、创建目录／临时文件、写入、替换、清理和完成；`error_kind` 是固定的文件错误类别。清理另有错误时由 `cleanup_error_kind` 标明，不覆盖最先失败的阶段。

Java 文件异常不会保存路径或原始错误文本，也不会从本地化错误信息猜测 Win32 错误码。这些事件记录显示配置的保存结果。

Windows 原生配置句柄允许祖先目录（包括游戏共享的 `config`）读写共享，避免阻止同目录下其他设置的原子替换；目录仍拒绝删除共享并复验身份／重解析点。私有配置的用户专属 ACL 和单实例锁不因此放宽，不需要修改整个游戏目录的权限。

## 反馈内容

发送「复制诊断」内容，或者 `startup.log` 与存在时的 `startup.log.1`，并附上 Minecraft／Loader 版本、使用的 JAR 或 ZIP 名称及最短复现步骤。

**不要提交 `config/p2wlan-private/`、账号密码、会话 token 或未检查的 HMCL／Minecraft 完整日志。** 若需要额外原始日志，应先检查和脱敏，再明确确认接收方。维护者依据启动阶段、失败操作和系统错误码核对根因。
